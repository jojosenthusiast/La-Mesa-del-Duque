# v0.5.0 — Gobernanza Progresiva de Calidad

## Resumen ejecutivo

La versión 0.5.0 integra el Quality Governance Pipeline v1 al flujo de integración continua de La Mesa del Duque. A partir de esta versión, los controles de calidad del proyecto dejan de ser verificaciones manuales para convertirse en validaciones progresivas, medibles y auditables, ejecutadas automáticamente en cada Pull Request.

Este cambio no agrega funcionalidad de negocio directa. Su valor está en elevar la gobernanza de calidad del proyecto a un nivel auditable y en establecer la infraestructura para compuertas bloqueantes en sprints futuros.

---

## Cambios principales

| Área | Cambio | Resultado |
|------|--------|-----------|
| Trazabilidad | Validación automatizada de trazabilidad documental en CI | Cada PR valida que la matriz de trazabilidad y los artefactos de calidad estén alineados |
| Evidencia de PR | Validación automatizada de evidencia de calidad en Pull Requests | Cada PR es evaluado contra criterios de evidencia de calidad |
| Suite de regresión | Pruebas marcadas con `Category=Regression` ejecutadas en CI | La suite de regresión se ejecuta automáticamente en cada build |
| Métricas de cobertura | Generación de métricas de cobertura en CI | Cobertura de código medible y publicada como artefacto |
| Paquete de evidencia | Publicación de artefactos de calidad desde GitHub Actions | Evidencia de calidad auditable disponible por build |
| Modo progresivo | `QUALITY_GATE_MODE` como interruptor de severidad | Permite pasar de advertencias progresivas a compuertas bloqueantes cuando el proyecto esté listo |

---

## Impacto funcional

- **Stakeholders**: cuentan con evidencia publicada de que los controles de calidad se ejecutan en cada entrega.
- **Equipo técnico**: recibe retroalimentación automatizada sobre trazabilidad, evidencia y regresiones antes del merge.
- **Revisores**: disponen de artefactos de calidad descargables para auditoría.

---

## Impacto técnico

- Se agrega el job `gobernanza` al workflow de CI (`.github/workflows/ci.yml`).
- Se agregan scripts de validación en `scripts/quality/`:
  - `validar-trazabilidad.ps1` — validación de trazabilidad documental.
  - `validar-pr-evidencia.ps1` — validación de evidencia de calidad en PRs.
  - `generar-metricas.ps1` — generación de métricas de cobertura.
  - `generar-paquete-evidencia.ps1` — empaquetado de artefactos de calidad.
- Se agregan tests Pester en `tests/quality/quality-scripts.Tests.ps1`.
- La suite de regresión `.NET` se ejecuta con el filtro `Category=Regression`.

## Riesgos y mitigaciones

| Riesgo | Severidad | Mitigación |
|--------|-----------|------------|
| `QUALITY_GATE_MODE=warning` no bloquea CI | Media | El modo progresivo es intencional; se escalará a `strict` cuando el equipo haya cerrado todos los hallazgos actuales |
| Scripts PowerShell dependen de la estructura del repo | Baja | Los tests Pester validan los scripts ante cambios estructurales |
