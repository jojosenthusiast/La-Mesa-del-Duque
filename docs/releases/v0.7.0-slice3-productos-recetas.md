# v0.7.0 — Slice 3: Productos y Recetas

## Resumen ejecutivo

La línea 0.7.0 incorpora el cierre backend de **Productos + Recetas** para Sprint 1. Este slice endurece el comportamiento del catálogo para alinearlo mejor con los criterios de aceptación de HU-011 y agrega la base de recetas necesaria para HU-014, permitiendo modelar instrucciones de preparación e ingredientes requeridos por producto.

El cambio no resuelve todavía el descuento automático de inventario al confirmar pago — ese flujo depende de slices posteriores del POS y de integración más profunda entre pedido, pago e inventario. Pero sí deja lista la estructura de dominio, aplicación y persistencia para hacerlo sin improvisaciones.

---

## Cambios principales

| Área | Cambio | Resultado |
|------|--------|-----------|
| Catálogo de productos | El precio del producto ahora debe ser **mayor que cero** | Se elimina la ambigüedad anterior que aceptaba precio cero |
| DTO y mapeos | `ProductoDto` ahora expone `ImagenUrl` y `TiempoPreparacionMin` | El backend devuelve información más cercana al criterio funcional del catálogo |
| Actualización de productos | `ActualizarProductoAsync` ahora permite ajustar imagen y tiempo de preparación | El servicio cubre mejor el criterio “editar cualquier campo” |
| Navegación de receta técnica | `Producto` ahora expone navegación explícita a `ProductoIngrediente` | EF deja de depender de una relación huérfana en configuración |
| Recetas | Se agregan `RecetaProducto` y `RecetaIngrediente` | El sistema ya puede registrar instrucciones e ingredientes por producto |
| Servicios de recetas | Se agrega `RecetasProductosServicio` y sus DTOs | El caso de uso de asociar y consultar recetas queda formalizado |
| Persistencia | Se agregan repositorios de ingredientes y recetas + migración EF | La base queda preparada para persistir el nuevo agregado |

---

## Impacto funcional

- **Encargado**: puede trabajar con productos que ahora reflejan mejor la información esperada del catálogo (precio válido, imagen y tiempo de preparación visibles desde backend).
- **Catálogo**: el backend ya no permite productos “gratuitos por accidente” por validar precio cero como válido.
- **Recetas**: el sistema ya puede asociar una receta con instrucciones y lista de ingredientes a un producto, base indispensable para HU-014.

  - `IRecetaProductoRepositorio`

  - `IngredienteRepositorio`
  - `RecetaProductoRepositorio`
- Se amplían:
  - `IUnidadDeTrabajo`
  - `UnidadDeTrabajo`
  - `InyeccionAplicacion`
  - `InyeccionInfraestructura`
- Se genera la migración:
  - `AgregarRecetasProductosSprint1`

### Decisión arquitectónica relevante

Se implementó **Receta** como agregado independiente del producto, en lugar de meter instrucciones e ingredientes directamente dentro de `Producto` como un objeto improvisado. Esto mantiene mejor separación de responsabilidades:

- `Producto` sigue representando el ítem vendible del catálogo.
- `RecetaProducto` representa cómo se prepara ese producto.
- `ProductoIngrediente` y `RecetaIngrediente` quedan separados por intención actual del sistema, aunque esta dualidad deberá revisarse en una futura consolidación si genera fricción.

## Criterios de aceptación cubiertos

### HU-011 — Gestión de productos

- **CA-52**: mejor cobertura backend al incluir descripción, imagen, precio, categoría y tiempo de preparación en creación/lectura de producto.
- **CA-53**: mejor cobertura backend al permitir editar imagen y tiempo de preparación además de nombre, precio, categoría y descripción.
- **CA-54**: se mantiene soft delete (`activo=false`).
- **CA-56**: se mantiene validación de categoría existente.

> Nota: la cobertura completa end-to-end de HU-011 todavía depende de la UI y del flujo de catálogo visible en POS.

### HU-014 — Recetas

- **CA-67**: cubierta a nivel backend — ya se pueden asociar ingredientes a un producto.
- **CA-68**: cubierta parcialmente a nivel estructural — el agregado de receta ya soporta cambios, aunque faltan operaciones más completas de edición/eliminación orientadas a UI.
- **CA-69 a CA-71**: todavía pendientes de integración con el flujo de confirmación de pedido/pago e inventario.

## Riesgos y mitigaciones

| Riesgo | Severidad | Mitigación |
|--------|-----------|------------|
| Duplicidad conceptual entre `ProductoIngrediente` y `RecetaIngrediente` | Media | Mantener documentada la distinción y revisar consolidación en una iteración futura |
