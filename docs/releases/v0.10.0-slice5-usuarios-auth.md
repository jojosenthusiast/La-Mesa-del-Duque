# v0.10.0 — Slice 5: Gestión de usuarios, login y autorización por roles

## Resumen ejecutivo

La línea 0.10.0 incorpora la base completa de **usuarios, autenticación y autorización** para Sprint 1. Este slice agrega gestión de usuarios con BCrypt, login/logout por cookies con timeout deslizante de 8 horas, claims de rol y middleware de autorización, cubriendo el backend de HU-021 y HU-025.

El sistema ahora puede diferenciar quién está operando, con qué permisos, y proteger endpoints según el rol del usuario autenticado. Esto es prerrequisito para cualquier flujo de UI que requiera control de acceso.

---

| Área | Cambio | Resultado |
|------|--------|-----------|
| Dominio | Entidad `Usuario` con métodos de activación, desactivación, cambio de rol y contraseña | El dominio encapsula las reglas de estado del usuario |

| Pruebas | 137 tests unitarios para `UsuariosServicio` | Suite completa llega a 192 tests |

## Impacto funcional

- **Administrador**: puede crear, editar, activar y desactivar usuarios, y asignarles roles.
- **Todos los roles**: acceden al sistema mediante login con usuario y contraseña. La sesión persiste 8 horas con timeout deslizante (se renueva en cada request).
- **Usuarios desactivados**: no pueden iniciar sesión aunque sus credenciales sean correctas.
- **Soft delete**: los usuarios no se eliminan físicamente; se marcan como inactivos, preservando la trazabilidad de auditoría.

## Impacto técnico

- Se agrega `Usuario` como entidad de dominio con:
  - `Desactivar()`, `Activar()`, `CambiarRol()`, `ActualizarUltimoAcceso()`, `CambiarPasswordHash()`
- Se amplía `IUsuarioRepositorio` con `ObtenerPorUsernameAsync`, `ObtenerTodosAsync`, `AgregarAsync`
- Se agrega `IRolRepositorio` con `ObtenerPorIdAsync`, `ObtenerPorNombreAsync`, `ObtenerTodosAsync`
- Se agregan implementaciones:
  - `UsuarioRepositorio`
  - `RolRepositorio`
- Se amplían `IUnidadDeTrabajo`, `UnidadDeTrabajo`, `InyeccionAplicacion`, `InyeccionInfraestructura`
- Se configura autenticación en `Program.cs`:
  - `AddAuthentication(CookieAuthenticationDefaults...)` con `LoginPath = "/Auth/Login"` y `LogoutPath = "/Auth/Logout"`
  - `ExpireTimeSpan = TimeSpan.FromHours(8)` con `SlidingExpiration = true`
  - Claims de rol (`ClaimTypes.Role`) incluidos en el principal al autenticar
- Se agregan páginas Razor:
  - `Pages/Auth/Login.cshtml` + `Login.cshtml.cs`
  - `Pages/Auth/Logout.cshtml` + `Logout.cshtml.cs`
- Se agrega `BCrypt.Net-Next` como dependencia en `LaMesaDelDuque.Aplicacion`

### Decisión arquitectónica relevante

Se eligió **cookie authentication** sobre JWT para este slice porque:
1. La aplicación es Razor Pages server-rendered, no una SPA — las cookies son el mecanismo nativo.
2. El timeout deslizante de 8h cubre el caso de uso del turno del restaurante sin forzar re-login.
3. La protección CSRF viene incluida con Razor Pages + cookies, sin configuración adicional.

Si en el futuro se agrega una API REST o una SPA, se evaluará agregar JWT como esquema complementario sin reemplazar las cookies existentes.

## Riesgos y mitigaciones

| Riesgo | Severidad | Mitigación |
|--------|-----------|------------|
| Usuario admin sin seed automático | Media | La estructura de roles y usuarios está lista; el seed se implementará en la fase de despliegue (Slice 7+) |
| Timeout de 8h puede ser largo para ambientes compartidos | Baja | Configurable en `Program.cs`; se puede reducir por ambiente |
| No hay protección contra brute force en login | Media | Se abordará en un slice futuro con rate limiting o lockout tras N intentos fallidos |
