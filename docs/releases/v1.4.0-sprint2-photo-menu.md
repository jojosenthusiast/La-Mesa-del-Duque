# v1.4.0 — Slice 4: Menú Visual con Fotos

## Resumen ejecutivo

La versión 1.4.0 transforma el catálogo de productos de una lista textual a una galería visual donde cada producto muestra su foto. Este cambio acelera la identificación de productos por parte del mesero (especialmente en menús extensos) y mejora la presentación hacia el cliente en la vista tableside. El sistema soporta upload de imágenes desde el panel de administración con validación de formato y tamaño, y renderiza placeholders elegantes para productos aún sin foto.

El slice incluye una corrección técnica importante: la serialización JSON de las páginas Razor ahora usa `CamelCase` consistentemente, alineando el contrato entre servidor y cliente JavaScript. Esto evita bugs silenciosos donde el frontend esperaba `producto.imagenUrl` pero recibía `Producto.ImagenUrl`.

## Impacto funcional

- **Fotos en grid POS**: cada producto muestra su imagen; el mesero identifica visualmente sin leer nombres
- **Upload admin**: drag & drop o click para seleccionar archivo; preview inmediato; validación de 5MB
- **Formatos soportados**: JPG, PNG, WebP; rechazo de otros formatos con toast de error
- **Placeholder elegante**: productos sin foto muestran icono de plato en gris; no rompen el layout
- **Tableside**: fotos grandes para que el cliente vea el plato mientras ordena desde la tablet
- **Serialización consistente**: todas las APIs JSON usan camelCase; elimina clase de bugs silenciosos

## Impacto técnico

- Modificado `Producto`:
  - Nuevo campo `ImagenUrl: string?` — ruta relativa a `/uploads/productos/`
  - Nueva propiedad computada `TieneImagen: bool` — `!string.IsNullOrEmpty(ImagenUrl)`
- Modificado `Pages/Operaciones/Productos/Index.cshtml` + `.cshtml.cs`:
  - Input file `<input type="file" accept="image/jpeg,image/png,image/webp">`
  - Validación en servidor: tamaño ≤ 5MB, extensión permitida
  - Guardado en `wwwroot/uploads/productos/{guid}.{ext}`
  - Preview en `<img>` antes de submit
- Modificado `Pages/Operaciones/Pedidos/Index.cshtml`:
  - Grid de productos: `.producto-card` con `<img>` condicional
  - CSS `.producto-img` y `.producto-placeholder`
- Modificado `Pages/Operaciones/Pedidos/Tableside.cshtml`:
  - Fotos más grandes (200px) para visualización del cliente
- Fix JSON:
  - `JsonSerializerOptions` con `PropertyNamingPolicy = JsonNamingPolicy.CamelCase`
  - Aplicado en todos los `PageModel` que retornan `JsonResult`

### Decisión arquitectónica relevante

Se eligió **almacenar imágenes en disco (`wwwroot/uploads/`)** en lugar de BLOB en base de datos porque:

1. **Performance**: servir archivos estáticos es más rápido que stream BLOB desde SQL.
2. **Escalabilidad**: si en el futuro se necesita CDN, las rutas ya están desacopladas de la DB.
3. **Backup**: el directorio `uploads` se puede sincronizar independientemente de la base de datos.

La contraparte es que se debe configurar persistencia del directorio en despliegues (volumen Docker o bucket S3). Para el MVP local, disco es suficiente.

## Riesgos y mitigaciones
