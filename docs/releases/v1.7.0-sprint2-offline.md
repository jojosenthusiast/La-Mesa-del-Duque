# v1.7.0 — Slice 7: Modo Offline

## Resumen ejecutivo

La versión 1.7.0 convierte la aplicación en una Progressive Web App (PWA) capaz de operar sin conexión a internet. Este es un requisito crítico para restaurantes donde la conexión WiFi puede ser inestable: los meseros pueden seguir tomando pedidos, la cocina puede seguir viendo órdenes, y los pagos pueden registrarse localmente para sincronización posterior. El modo offline se implementa mediante Service Worker con estrategia network-first, IndexedDB para cola de pedidos y pagos pendientes, y polling AJAX como fallback para el KDS cuando SignalR no está disponible.

La sincronización es transparente: al recuperar la conexión, el sistema envía automáticamente los pedidos y pagos acumulados, actualiza el KDS con el estado actual de la cocina, y reconcilia cualquier conflicto de estado.

- **Pagos offline**: mesero registra pago en modo offline; se encola para sync posterior
- **Detección visual**: banner superior rojo "Sin conexión" / verde "Conexión restablecida"

- **KDS diff updates**: solo las tarjetas que cambiaron se actualizan; sin parpadeo ni re-render completo
- **Sync automático**: reconexión → envía pedidos → envía pagos → refresca estado → banner verde
- **Fallback branded**: si ni siquiera el cache funciona, `offline.html` muestra logo y mensaje profesional

## Impacto técnico

- Nuevo `wwwroot/manifest.json`:
  - `name`, `short_name`, `icons`, `start_url`, `display: standalone`
  - Theme colors alineados con branding de La Mesa del Duque
- Nuevo `wwwroot/sw.js`:
  - `install`: cachea shell de app (CSS, JS, HTML)
  - `fetch`: network-first; si falla, sirve desde cache
  - `sync`: `sync` event para background sync (donde el browser lo soporte)
- Nuevo `wwwroot/js/offline.js`:
  - `registrarServiceWorker()`: registra `sw.js` con scope `/`
  - `detectarConexion()`: listeners de `online`/`offline` events
  - `encolarPedido(pedido)`: guarda en IndexedDB `LMDD-Offline` → `pedidosPendientes`
  - `encolarPago(pago)`: guarda en `pagosPendientes`
  - `sincronizarTodo()`: lee colas, envía al servidor, limpia al confirmar
- IndexedDB schema:
  - DB: `LMDD-Offline`
  - Stores: `pedidosPendientes` (keyPath: `id`), `pagosPendientes` (keyPath: `id`), `meta` (última sync)
- Modificado `KDS.cshtml.cs`:
  - `OnGetEstadoActualJsonAsync()`: retorna `JsonResult` con lista de `OrdenCocina` activas
- Modificado `kds.js`:
  - `connection.onclose(() => iniciarPolling())`
  - `iniciarPolling()`: `setInterval(fetchEstado, 5000)`
  - `aplicarDiff(nuevasOrdenes)`: compara con estado actual, solo actualiza DOM de tarjetas modificadas
- Nuevo `wwwroot/offline.html`:
  - Branded con logo, mensaje "Modo offline", instrucciones de reconexión

### Decisión arquitectónica relevante

Se eligió **network-first en el Service Worker** en lugar de cache-first porque:

1. **Datos frescos**: el POS y KDS requieren estado actualizado; cache-first mostraría datos obsoletos.
2. **Recursos estáticos**: CSS/JS se cachean en install; si la red falla, la app shell funciona.
3. **Graceful degradation**: network-first intenta servidor primero; solo si falla, sirve cache. Esto prioriza correctitud sobre velocidad.

La cola offline (IndexedDB) maneja las operaciones de escritura (pedidos, pagos) que no pueden esperar al servidor.

## Riesgos y mitigaciones

| Riesgo | Severidad | Mitigación |
|--------|-----------|------------|
| Sync de pedidos offline en orden incorrecto | Media | Cola FIFO en IndexedDB; pedidos se envían en orden de creación |
| Pago offline con cuenta ya pagada por otro terminal | Media | Servidor verifica estado cuenta antes de procesar; retorna 409 si ya pagada |
| Service Worker no soportado en browser antiguo | Baja | Graceful fallback; app funciona como web normal sin SW |
| IndexedDB quota excedida en tablet barata | Baja | Limpieza post-sync; TTL de 7 días para registros no sincronizados |
