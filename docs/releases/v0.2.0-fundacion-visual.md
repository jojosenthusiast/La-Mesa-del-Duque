# v0.2.0 — Fundación Visual

**Fecha de publicación**: 1 de mayo de 2026
**Rama base**: `main` (desde `feature/fundacion-visual-marca`)
**Commit de referencia**: `db3cf42` — `feat(marca): integrar fundación visual`

---

## Resumen ejecutivo

La versión 0.2.0 establece la identidad visual del sistema La Mesa del Duque. Se integró una marca profesional con personalidad española —paleta cromática, tipografía, logotipos y tokens de diseño CSS— y se protegió el repositorio contra la inclusión accidental de artefactos de flujo de trabajo local. También se crearon los primeros wireframes base como guía visual para el desarrollo de la interfaz de usuario. Esta versión no introduce funcionalidad de negocio; sienta la base estética y de diseño sobre la que se construirá toda la experiencia de usuario.

## Impacto funcional

- **Usuarios finales**: La interfaz ahora presenta una apariencia profesional coherente con la marca, proyectando elegancia, confianza y profesionalismo alineados con el concepto del restaurante.
- **Desarrolladores**: Disponen de una guía de marca, tokens de diseño y wireframes como referencia vinculante para cualquier trabajo de interfaz de usuario. Todo componente visual debe adherirse a esta especificación.
- **Stakeholders**: La identidad visual está definida formalmente y es verificable mediante la documentación de diseño. Esto reduce la ambigüedad en la revisión de entregables visuales.

---

## Impacto técnico

- **Nuevo archivo CSS de marca** (`marca.css`): encapsula todos los tokens y estilos de componentes. Se carga junto con `site.css` en el layout compartido. Cualquier cambio en la marca se centraliza aquí.
- **Tokens CSS como fuente de verdad**: Los tokens definidos en `docs/diseno/tokens-de-diseno.md` tienen su implementación concreta en `marca.css`. La documentación y el código están alineados.
- **Sin dependencia de frameworks externos**: Los estilos de marca son CSS plano y no introducen dependencias adicionales. Son compatibles con Bootstrap 5.3.
- **Prevención de contaminación del repositorio**: `.gitignore` ahora bloquea la inclusión de artefactos de herramientas de planificación (`.atl/`, `openspec/`, etc.) que son propios del flujo de trabajo local de cada desarrollador.

## Riesgos, límites y decisiones

### Riesgos identificados

- **Consistencia de marca en el tiempo**: Si los desarrolladores no consultan la guía de marca antes de crear nuevas interfaces, podrían desviarse del estándar visual. **Mitigación**: la guía es parte del checklist de revisión de código y de la definición de hecho.

### Límites de esta versión

- Esta versión no incluye funcionalidad de negocio. Es puramente visual y de infraestructura de proyecto.
- Los wireframes de POS, cocina y despacho son conceptuales y se refinarán durante los sprints correspondientes.
- No se implementaron pruebas automatizadas para los estilos visuales (pruebas de regresión visual quedan pendientes para una versión futura).

### Decisiones relevantes

| Decisión | Justificación |
|----------|---------------|
| **Paleta cromática con personalidad española** | Azul Duque y Dorado Real evocan realeza y elegancia; Marfil aporta calidez; los colores funcionales (verde, terracota, gris) mantienen usabilidad estándar |
| **Fuentes Cinzel + Montserrat** | Cinzel (serif) para títulos transmite distinción clásica; Montserrat (sans-serif) para cuerpo garantiza legibilidad moderna. Ambas disponibles en Google Fonts sin costo |
| **Logotipos como imágenes PNG** | Seis variantes cubren todos los contextos (web, impresión, favicon, fondos claros/oscuros). Formato PNG elegido por compatibilidad universal |
| **CSS plano sin preprocesador** | Minimiza dependencias de build y mantiene compatibilidad directa con ASP.NET Core. Los tokens pueden migrarse a Sass/postCSS en el futuro si la complejidad lo justifica |
| **Exclusión de herramientas de planificación en `.gitignore`** | `.atl/`, `openspec/`, `.claude/`, `.sdd/`, `AGENTS.md` y `CLAUDE.md` son artefactos del flujo de trabajo individual de cada desarrollador y no deben versionarse |

## Próximos pasos

1. **Definir el modelo de dominio**: implementar las entidades de negocio del restaurante (productos, pedidos, mesas, recetas, usuarios) con sus invariantes y reglas de dominio.
2. **Aplicar la marca a nuevas páginas**: a medida que se desarrollen las vistas de POS, cocina, inventario y administración, usar los tokens y componentes definidos en `marca.css`.
3. **Pruebas de regresión visual**: evaluar herramientas como Percy o Chromatic para detectar regresiones visuales automáticamente.
4. **Accesibilidad**: realizar una auditoría formal de accesibilidad WCAG 2.1 AA sobre las páginas implementadas.
