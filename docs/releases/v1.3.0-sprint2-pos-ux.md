# v1.3.0 — Slice 3: POS UX Optimizada

## Resumen ejecutivo

La versión 1.3.0 transforma la experiencia del punto de venta de una interfaz funcional pero rudimentaria a un sistema operativo fluido y profesional. El cambio central es la eliminación completa de `alert()` y `confirm()` nativos del navegador, reemplazados por un sistema de toast notifications y modales de confirmación basados en Promises que no bloquean el hilo de ejecución. El mesero puede ahora operar a velocidad con atajos de teclado, recibir feedback visual inmediato y recuperar su estado si recarga la página.

Este slice no agrega funcionalidad de negocio nueva, pero multiplica la productividad operativa al eliminar fricción. Las mesas tienen codificación de color por estado, el flujo de pedido tiene un indicador visual de 3 pasos, y cada acción del mesero recibe feedback inmediato mediante animaciones y notificaciones.

## Impacto funcional

- **Sin bloqueos**: ningún `alert()` o `confirm()` nativo queda en el POS; toda interacción es no-bloqueante
- **Toast notifications**: mensajes de éxito/error/aviso aparecen en esquina inferior derecha, auto-dismiss 3s
- **Modal confirmation**: al eliminar ítem o cancelar pedido, modal centrado con cancelar/confirmar
- **Colores de mesa**: glancing visual del estado de la sala sin entrar a cada mesa
- **Propina**: selección rápida 10/15/20% o monto custom; calcula total automáticamente
- **Atajos de teclado**: flujo completo de pedido sin mouse (navegación mesa → producto → confirmar → enviar)
- **Persistencia**: si el mesero recarga accidentalmente, el pedido en construcción se restaura desde localStorage
- **Indicador de pasos**: barra superior con 3 pasos iluminados según progreso, reduce errores de secuencia

## Impacto técnico

- Nuevo archivo `wwwroot/js/toast.js`:
  - `showToast(message, type = 'info', duration = 3000)`
  - Tipos: success, error, warning, info
  - Sin dependencias externas; puro CSS + JS
- Nuevo archivo `wwwroot/js/modal.js`:
  - `confirmAsync(message)` retorna `Promise<boolean>`
  - `showModal(config)` para modales personalizados
  - Tecla `Enter` confirma, `Escape` cancela
- Modificado `wwwroot/js/pos.js`:
  - Todos los `alert()` reemplazados por `showToast()`
  - Todos los `confirm()` reemplazados por `await confirmAsync()`
  - Registro de atajos: `document.addEventListener('keydown', ...)`
  - Funciones `guardarEstadoLocal()` y `restaurarEstadoLocal()`
- Modificado `Pages/Operaciones/Pedidos/Index.cshtml`:
  - Nuevo `<div id="toast-container">` para anclaje de toasts
  - Nuevo `<div id="modal-overlay">` para modales
  - Barra de pasos visual: `<div class="step-indicator">`
  - CSS para colores de mesa: clases `.mesa-libre`, `.mesa-ocupada`, `.mesa-cuenta`, `.mesa-pagada`
- localStorage key: `LMDD-POS-{mesaId}` guarda serialización JSON del pedido en construcción

### Decisión arquitectónica relevante

Se eligió **Promise-based modales en lugar de callbacks** porque:

1. **Async/await natural**: el código del POS ya usa async para llamadas al servidor; los modales encajan sin cambiar el estilo de control de flujo.
2. **Componibilidad**: se puede hacer `if (await confirmAsync("¿Cancelar?")) { ... }` de forma lineal, sin anidamiento de callbacks.
3. **Testabilidad**: los modales son funciones puras que retornan Promises; se pueden mockear en tests sin manipular DOM.

La alternativa (callbacks o eventos globales) habría fragmentado la lógica del POS y dificultado la lectura del flujo de pedido.

## Riesgos y mitigaciones

| Riesgo | Severidad | Mitigación |
|--------|-----------|------------|
| localStorage lleno en dispositivos antiguos | Baja | TTL de 24h; limpieza automática al completar pedido |
| Atajos de teclado conflictivos con browser | Baja | Solo Ctrl+combinaciones; testeado en Chrome/Edge/Firefox |
| Toast tapa botones importantes | Baja | Posición inferior-derecha; auto-dismiss 3s; manual dismiss con click |
