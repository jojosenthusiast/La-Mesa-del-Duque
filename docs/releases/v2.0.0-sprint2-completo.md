# v2.0.0 — Sprint 2 Completo: Experiencia operativa y pagos

## Resumen ejecutivo

La versión 2.0.0 marca la entrega integrada del Sprint 2 de La Mesa del Duque. El sistema evoluciona de una plataforma operativa básica a una experiencia completa de restaurante con 9 nuevas funcionalidades: pantalla de cocina con columnas multi-cocinero, modificadores de ingredientes al momento de pedir, experiencia POS optimizada sin popups bloqueantes, menú visual con fotos, arquitectura de pago real con sub-cuentas, división por ítems, vista tableside para tablet, modo offline con PWA y sincronización entre terminales vía SignalR.

Este release incluye backend completo (4 nuevas entidades de dominio: OrdenCocina, Cuenta, Pago, CuentaDetalle), frontend operativo (5 nuevas páginas Razor: KDS, Tableside, Productos con fotos, POS mejorado, offline), infraestructura de calidad (271 tests, +64 tests nuevos) y documentación canónica actualizada (9 HUs, 25 CAs).

### Infraestructura técnica

- **KDS**: Pantalla full-screen con 3 columnas por cocinero, color por tiempo de preparación, alerta sonora, polling fallback offline
- **POS UX**: Notificaciones toast inline (sin alert/confirm), atajos de teclado, persistencia localStorage, indicador de pasos
- **Pagos**: Arquitectura de sub-cuentas (Cuenta/Pago) con división por ítems, método de pago por cuenta, propina, auditoría de usuario
- **Modificadores**: Modal maestro-detalle de ingredientes con alergias, quitados (motivo: alergia/preferencia/intercambio) y extras
- **Offline**: PWA con Service Worker, cola IndexedDB para pedidos y pagos pendientes, sincronización automática, polling KDS
- **86/Agotado**: Cocina marca producto agotado → SignalR sincroniza a todos los terminales POS
- **Course firing**: Agrupación de ítems por curso (Entrada/PlatoFuerte/Postre) con disparo controlado
- **Autenticación**: Cookies + BCrypt, timeout deslizante, bloqueo tras 5 intentos, force-logout al cambiar rol
- **Autorización**: Claims de rol, `[Authorize]` por página. Cocinero restringido de POS/Admin
- **Base de datos**: PostgreSQL (Supabase) producción, SQLite desarrollo
- **CI/CD**: GitHub Actions (build, test, regresión, CodeQL, Gitleaks, gobernanza)
- **Release**: Release Please configurado + documentación curada

## Issues corregidos en Sprint 2

| Issue | Causa | Fix |
|-------|-------|-----|
| `alert()`/`confirm()` bloqueando UI | POS original usaba popups nativos | Sistema de toast + modal inline |
| Serialización JSON PascalCase vs camelCase | `JsonSerializer` sin `CamelCase` policy | `JsonNamingPolicy.CamelCase` en todas las páginas |
| `IUnidadDeTrabajo` sin `OrdenesCocina`/`Cuentas` | Merges entre ramas divergentes | Unificación manual de interfaces |
| 5 tests rotos (Guid.Empty) | `DetallePedido.Id` no asignado en constructor | `Id = Guid.NewGuid()` en constructor |
| SQLite sin columnas de migraciones | DB vieja sin migraciones de Sprint 2 | Recreación de DB con nuevo esquema |
| CSRF faltante en 5 formularios | Formularios sin `@Html.AntiForgeryToken()` | Agregado a Productos, Mesas, Usuarios, Logout |
| Bloqueo de login incorrecto | 5 intentos por minuto, no consecutivos | Bloqueo tras 5 fallos consecutivos, 15 minutos |
| Sin timeout por inactividad | `SlidingExpiration=true` sin `IdleTimeout` | `IdleTimeout` configurado |
| Cambio de rol sin force-logout | Sin invalidation de sesión | `SecurityStamp` al cambiar rol |
